RankBind Phase 1 — Diagnostic Report & Plan Pivot

2026-04-21  ·  HPC / Leipzig  ·  rankbind/evaluation/

TL;DR

The original Phase 1 goal — demonstrate universal attractor bias across DTI models via Gini — does not survive a proper null baseline. A data-only model that ignores ligands produces Gini ≈ 0.995, the same value as every trained model. Gini is a dataset-geometry artifact, not evidence of a learned pathology.

But the null-baseline probe uncovered something stronger: all four models achieve high global AUC while failing ligand-conditional ranking (per-ligand AUC ≤ 0.625). They learn protein-level shortcuts, not ligand-protein interaction.

The paper's deliverable changes from "diagnose the bias" to "design a DTI architecture that is provably attractor-resistant."

Glossary — read this first if terms below feel unfamiliar
DTI — Drug-Target Interaction
The task of predicting whether a small molecule (drug / ligand) binds to a given protein. In this project we use enzyme-substrate pairs from BRENDA, so "ligand" = substrate and "protein" = enzyme.
Score matrix
An N_lig × N_prot matrix where entry (i, j) is the model's predicted binding score for ligand i against protein j. High values should concentrate on true binding pairs. We use a 200×200 probe matrix for diagnosis.
Attractor score (per protein)
The fraction of ligands for which this protein is the model's top-1 prediction. A protein with attractor score 0.5 "wins" half of all ligands, regardless of which ligand. A model with no attractors has a flat distribution (every protein = 1/N_prot).
Gini coefficient
Inequality measure of the attractor-score distribution, in [0, 1]. Gini = 0: perfectly uniform (every protein gets the same share). Gini = 1: one protein wins every ligand. Why it's used here: it summarizes in one number how concentrated the predictions are on a few "attractor" proteins.
Protein-based split
Train/val/test partition by protein, not by pair. Guarantees no protein appears in both train and test — the correct discipline for measuring generalization to new proteins. Without this, a model can memorize per-protein labels and appear to generalize.
Null baseline
A synthetic "model" with no learned parameters. Used to check whether a metric is measuring the model or just the data geometry. Three are used here:
  • null_random: uniform noise scores.
  • null_prot_prior: score depends only on the protein's training positive rate (ligand ignored). This tests: "could a model that knows nothing about ligands still reproduce this metric?"
  • null_lig_prior: symmetric version for ligand.
Global AUC
Area Under the ROC Curve computed over all test pairs pooled together. Measures: "given a random positive and a random negative pair, how often does the model score the positive higher?" Ranges 0.5 (random) to 1.0. Shortcut risk: in a dataset where some proteins are almost always positive, a protein-only classifier scores very high here.
Per-ligand AUC
AUC computed within each ligand separately, then averaged across ligands. Measures: "for this specific ligand, does the model rank its true binding protein(s) above the non-binding proteins?" Unlike global AUC, this cannot be solved by a protein-only classifier — it directly tests whether the model uses ligand information. This is the metric that matters for DTI.
AUPR (Average Precision)
Area under the precision-recall curve. More sensitive than AUC when positives are rare. Reported alongside AUC for completeness.
Jaccard index (top-K)
Set-overlap measure between each model's top-K attractor proteins: |A ∩ B| / |A ∪ B|. Jaccard 1.0 = identical top-K; 0.0 = disjoint. We use K=10. Two models can have identical Gini yet Jaccard 0 — same statistics, different proteins.
Prior inheritance
When a trained model's top attractors match those of null_prot_prior (high Jaccard), the model has effectively learned the per-protein label distribution and nothing else. Diagnostic of shortcut learning.
Shortcut learning
The model relies on a spurious feature (here: per-protein label frequency) that correlates with the label on the training distribution but does not reflect the actual task (ligand-protein binding).
Response map
Heatmap visualization of the full score matrix. X-axis = protein, Y-axis = ligand, color = score. Vertical bands (bright columns) indicate attractor proteins — they win regardless of the ligand on the Y-axis. A well-behaved DTI model would show bright spots on the diagonal or scattered, not bands.

1. What the plan was

Phase 1 was scoped as an empirical diagnosis: train four published DTI models (GraphDTA, MolTrans, DrugBAN, GEMS) on the BRENDA protein-based split, compute 200×200 score matrices, and show that all models exhibit extreme attractor concentration via Gini ≫ 0.5. The narrative: "universal protein-attractor bias in DTI."

Phases B–D were executed successfully. Models trained, matrices produced, Gini computed. Every model landed at Gini ≈ 0.99. The story looked clean.

2. What the data actually says

Three diagnostics were added after the primary pipeline finished:

  • Null baselines (evaluation/null_baselines.py): three synthetic score matrices over the same 200×200 geometry: random, per-protein positive rate, per-ligand positive rate.
  • Cross-model attractor overlap (cross_model_overlap.py): top-10 Jaccard of attractor-protein identity between every model pair and the prior baseline.
  • Test-set evaluation (test_set_eval.py): global AUC/AUPR and per-ligand AUC on the held-out protein test split.
How to read this summary dashboard.
  • Top row (response maps): each panel is a 200×200 score matrix. Bright vertical bands mean "one protein wins many ligands" — the attractor signature. Notice how GraphDTA and MolTrans show the same banding pattern as null_prot_prior, a model that literally ignores the ligand axis.
  • Bottom-left (Jaccard): row/column i∩j = how many top-10 attractor proteins model i and model j share. Diagonal is always 1.0 (a model shares everything with itself). Consequence: the original framing collapses. Gini does not distinguish a data-blind baseline from a trained model. Any reviewer with a null baseline concern (any reviewer) closes the paper at this table.

Why does null_prot_prior produce Gini = 0.995?

null_prot_prior assigns each protein a single scalar — its training positive rate — and uses that scalar as the score for every ligand paired with that protein. So in the 200×200 matrix, each column is constant: all ligands get the same score for a given protein.

When you now compute "for which ligands is protein p the top-1?", the answer is: the protein with the highest positive rate wins every single ligand, up to ties. One protein gets attractor score ≈ 1.0, everyone else ≈ 0.0. That's maximum concentration → Gini ≈ 1.0.

This is why a model's matching Gini is not evidence of anything interesting: the dataset's per-protein label imbalance alone forces the metric to its ceiling. Detecting this required running the null baseline.

2.2 Attractor identity — partial prior inheritance

How to read the Jaccard heatmap. Each cell is a number in [0, 1]. 1.0 means "these two models / baselines pick the exact same top-10 attractor proteins"; 0.0 means "completely disjoint sets." The diagonal is trivially 1.0. To compare a model with the data prior, read the column (or row) of null_prot_prior: values close to 1.0 indicate the model has effectively learned the data's per-protein label distribution.
  • GraphDTA ↔ GEMS: 0.82 — two very different architectures (GCN on ligand vs GAT on complex with ESM2) pick nearly the same attractor proteins. Strong shared-shortcut signal.
  • GraphDTA ↔ null_prot_prior: 0.67 — two thirds of the top attractors would be predicted by a model that never sees a ligand.
  • MolTrans vs everyone else: all 0.05–0.18. MolTrans is the outlier, but with Gini = 0.987 it still collapses — just onto a different set of proteins.

Three models inherit the prior's top attractors. MolTrans deviates from the prior but still collapses onto its own attractor subset (its Gini is essentially identical).

2.3 The real problem — ranking AUC

Why Global AUC and Per-ligand AUC can disagree

Imagine a dataset with 10 proteins, each appearing in 100 test pairs. Seven proteins bind most ligands (80% of their pairs are positive); three proteins bind almost nothing (5% positive). Now consider a model that ignores ligands and scores each pair based only on the protein (high score for the seven frequent binders, low for the three rare ones).

  • Global AUC of this model ≈ 0.87 — it correctly separates positive-heavy proteins from negative-heavy proteins. Looks good.
  • Per-ligand AUC of this model = 0.5 — within any given ligand, it assigns the same score to all seven frequent-binder proteins (it can't tell them apart using the ligand). Random ranking.

Per-ligand AUC therefore isolates the information the model uses that actually depends on the ligand identity. A model scoring below 0.5 on this metric is using ligand information in an actively misleading way.

Global AUC ≥ 0.87 for three of four models looks like DTI is solved. But per-ligand AUC never exceeds 0.625, and for DrugBAN/GEMS it is below random. Per-ligand AUC is the meaningful metric: given this ligand, rank the candidate proteins. None of the four models can do this.

The models learn a protein-level shortcut. Global AUC is inflated because most pairs with a "frequent-binder" protein are positives. Flip to the ligand-conditional view and the signal disappears.

How to read the per-ligand AUC column.
  • 0.5 = the model cannot rank candidate proteins for a given ligand better than coin flips. Equivalent to: "the model's ranking within a ligand contains no information about which protein actually binds that ligand."
  • < 0.5 (DrugBAN 0.375, GEMS 0.25) = the model is systematically anti-correlated with the truth on the within-ligand axis. It assigns higher scores to non-binders than binders for that ligand. (It still has high global AUC because cross-ligand differences dominate.)
  • 0.625 (GraphDTA) = weakly above random. This is as good as it gets in our Phase-1 set of baselines.
  • Takeaway: none of these models can answer the operational DTI question "given a new ligand, which enzyme is most likely to bind it?" — which is what matters for drug discovery, enzyme engineering, or substrate prediction.

3. Why the original plan does not work

  1. Null-baseline refutation. The headline metric (Gini) is reproduced by a data-blind baseline. The "universal attractor bias" claim is empirically correct but mechanistically trivial: the dataset geometry alone forces it.
  2. Missing metric. Global AUC was never a sufficient success criterion for DTI. Three "good" models have per-ligand AUC ≤ 0.5. Any model we "validate" with global AUC is a model that has learned the prior.
  3. The interesting finding is absent from the plan. The actual scientific content is: DTI models converge on protein-level shortcuts under protein-based splits. None of the scheduled Phase-1 deliverables surfaces this directly.
  4. GIGN strategy is no longer load-bearing. Adding a fifth model does not change the diagnosis. SKiD/DiffDock compute time (weeks of GPU) has no payoff under the new framing.

Retain

  • attractor_diagnosis.py, null_baselines.py, cross_model_overlap.py, test_set_eval.py — these stay as the empirical skeleton.
  • The unified protein-based split in common.py.

  • Phase C (complex 3D models) as originally scoped
  • Regression-vs-Binary ablation (not informative under the new framing)

Add

  • Per-ligand AUC as primary reporting metric. Global AUC demoted to context.
  • Prior-adjusted metrics: gini_residual = gini(model) − gini(prior); attractor-Jaccard vs prior.
  • A new Phase 2 focused on architecture design (see §5).

5. New paper direction — a specific architecture that solves this

The target contribution shifts from "benchmarks are broken" (negative result, common genre) to "here is a DTI architecture that passes ligand-conditional ranking where standard models fail" (positive result, method contribution).

Working title. RankBind: Protein-Invariant Contrastive Learning for Ligand-Conditional DTI.

Claim. A DTI model trained with (a) protein-balanced sampling, (b) within-ligand contrastive loss, and (c) a bilinear-only interaction head achieves per-ligand AUC ≥ X on BRENDA while matching the best baseline's global AUC, unlike all four evaluated baselines which score ≤ 0.625.

5.1 Architectural components

(a) Protein-balanced sampling

Each training epoch samples a near-equal number of positives and negatives per protein. Eliminates the protein-level label prior that the four baselines exploit. Directly removes the shortcut signal that produces null_prot_prior's Gini ≈ 0.995.

Intuition. If protein P appears 95× as a binder and 5× as a non-binder, the gradient updates predominantly say "high score for P." The model learns "P is a binder," not "P binds these ligands." Balanced sampling flips this: for every positive (L+, P) there is a comparable negative (L−, P), forcing the model to distinguish them — which it can only do by reading the ligand.

(b) Within-ligand contrastive loss

For every training ligand L with a positive protein P+, sample k protein negatives {P−i} and optimize a margin ranking loss: max(0, m − s(L, P+) + s(L, P−i)). The model is forced to assign higher score to the true protein for that specific ligand — which is exactly the per-ligand AUC criterion.

Intuition. Standard BCE loss optimizes absolute score (positive pairs → 1, negatives → 0). The model can minimize BCE by matching per-protein averages — no pairwise comparison needed. The margin loss is explicitly relative: the score of the true protein must beat the score of a specific other protein for the same ligand. The training objective becomes shape-matched to per-ligand AUC.

(c) Bilinear-only interaction head

The final score is s(L, P) = f(L)⊤ · M · g(P) + b, with no standalone MLP path that sees only L or only P. Eliminates the "protein-only" architectural shortcut (which DrugBAN/GEMS currently have via their BAN / GAT heads that project to a scalar with protein-prior leakage).

Intuition. Many DTI architectures concatenate a ligand embedding and a protein embedding into one vector, then pass through an MLP. An MLP with enough capacity will learn any function of just the protein part (weights zero on the ligand components → protein-only score). Forcing a bilinear form L⊤ M P means a non-trivial score requires contributions from both sides: if either f(L) or g(P) is constant across inputs, the model cannot score. This is an architectural prior against the shortcut.

5.2 Evaluation protocol

  • Same common.BRENDADataConfig protein-based split as Phase 1 (zero leakage to baselines).
  • Primary metric: per-ligand AUC (macro-mean across test ligands with ≥1 positive and ≥1 negative).
  • Secondary metrics: global AUC (for compatibility), Hit@K on a larger candidate set, attractor-Jaccard vs null_prot_prior (must approach zero for a non-shortcut model).
  • All four baselines are re-reported on per-ligand AUC (this report already has the numbers). RankBind must beat 0.625 by a meaningful margin to claim success.

5.3 Risk / falsifiability

If protein-balanced sampling + contrastive loss fails to lift per-ligand AUC above 0.65, the contribution is not a new architecture but a confirmed negative result — and the paper pivots back to "DTI benchmarks cannot separate shortcut from signal." That fallback is still publishable (as a measurement paper), but the primary target is the positive contribution.

6. Concrete next steps

  1. Week 1. Implement the three components as a minimal model (v5_rankbind/model.py): protein-balanced sampler, margin loss, bilinear head. Use ESM2 + ChemBERTa encoders (already available from GEMS pipeline) so the contribution is the training/architecture shape, not the encoders.
  2. Week 2. Train + evaluate on the same split. Report the same five metrics side-by-side with the four baselines.
  3. Week 3. Ablations: remove each of (a)/(b)/(c) to show they are individually necessary.
  4. Week 4. Cross-dataset probe: train on BRENDA, evaluate on a second enzyme-substrate corpus (kcat or similar) to test generalization under the same protein-based leakage discipline.
